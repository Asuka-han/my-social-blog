## 四、项目日志体系建议

项目日志体系建议遵循以下原则，确保日志规范、可追溯、易分析：

### 1. 日志模块选用

使用Python内置logging模块，无需额外安装第三方依赖，稳定性高、兼容性强。

### 2. 日志体系目录结构（推荐成熟方案）

```plain text
src/utils/
├── __init__.py
├── logger_config.py          统一日志配置模块（负责定义日志的规则、格式、输出方式等核心逻辑）
├── logger.py                 日志工具函数（提供简单、易用的日志调用接口）
├── output_manager.py         输出目录管理（不仅为日志文件提供目录路径，还能管理其他输出文件（如报表、数据文件、模型文件等））
└── ...其他模块
```

### 3. 日志级别使用规范

|级别|用途|示例|
|---|---|---|
|**DEBUG**|详细信息，仅用于诊断问题|数据转换步骤、中间变量值|
|**INFO**|重要的业务事件，记录正常流程|数据加载完成、分析开始/完成|
|**WARNING**|警告性信息，不影响程序运行但需关注|数据缺失、转换异常、性能下降|
|**ERROR**|错误事件，程序可继续运行|API调用失败、数据验证失败|
|**CRITICAL**|严重错误，程序可能无法继续运行|数据库连接失败、关键文件丢失|

### 4. 日志格式规范

建议使用结构化日志格式，确保每条日志都包含关键上下文信息，便于后续检索和分析。推荐格式模板如下：

%(asctime)s - %(name)s - %(levelname)s - %(filename)s:%(lineno)d - %(message)s

各字段说明：

- asctime：人类可读的时间戳（默认格式 YYYY-MM-DD HH:MM:SS,ms）；

- name：记录器名称（通常为模块名，如 __name__）；

- levelname：日志级别（DEBUG/INFO/WARNING/ERROR/CRITICAL）；

- filename：产生日志的文件名；

- lineno：产生日志的代码行号；

- message：具体的日志消息内容。

### 5. 日志轮转配置

为防止单个日志文件无限增大，占用过多存储空间，需配置日志轮转。Python的logging.handlers模块提供两种常用轮转策略：

- RotatingFileHandler：基于文件大小轮转，当文件达到指定大小时，自动重命名旧文件并创建新文件；

- TimedRotatingFileHandler：基于时间轮转，例如每天、每小时自动生成一个新的日志文件。

## 五、U盘交付要求

U盘交付内容需满足清晰、轻量、可复现的要求，具体打包内容如下：

- 项目核心源码、可执行.py文件：要求目录结构清晰，代码注释完整，便于查看和运行；

- 项目说明文档：包含使用流程、版本信息、注意事项等关键内容，方便使用者快速上手；

- 关键配置文件、依赖清单：确保环境可快速复现，避免因配置缺失导致无法运行；

- 测试数据/示例文件：仅保留必要的演示数据，避免占用过多存储空间，保证交付轻量。

## 六、导出YAML文件步骤

激活已创建的Python虚拟环境后，运行以下命令导出yml环境配置文件（建议命名为environment.yml，也可根据个人需求自定义文件名）：

```bash
conda env export --no-builds > environment.yml
```

补充说明：

1.  基础命令（未加--no-builds）：`conda env export > environment.yml`，导出内容会包含每个包的build编号，示例片段如下：

```yaml
dependencies:
  - python=3.9.18=h42ad0f4_0 # 包含build编号
  - numpy=1.24.3=py39h79a8e48_1
```

2.  推荐命令（加--no-builds）：会自动移除每个包的build编号，仅保留核心版本信息（如python=3.9.18），示例片段如下：

```yaml
dependencies:
  - python=3.9.18 # 仅保留版本号，无build编号
  - numpy=1.24.3
```

3.  关键提醒：若版本号指定过于细致（包含build编号），可能导致在其他电脑上复现环境时出现依赖冲突问题，因此优先推荐使用带--no-builds参数的导出命令。

## 七、项目工作流示例（仅供参考）

以下为开始或完善一个项目的大致工作流程，可根据实际需求灵活调整，提升项目推进效率：

1. 将.md格式的项目需求文件发送给AI（推荐使用GPT5.1），要求AI仔细研读需求，输出预期项目结构、按实施顺序排列的任务清单及交付文件清单。需确保每项任务包含具体可落地的实施要点，可直接转化为实际工作项；覆盖需求文档所有要求，重点关注易被忽略的细节。可将AI输出的内容发送给其他AI工具交叉检查，补充完善遗漏点。

2. 让AI按照输出的任务清单逐步完成工作，建议每次仅分配1-2个核心任务，避免任务过多导致遗漏或质量下降。

3. 完成单个或多个任务后，对照.md需求文件及预期项目结构，检查完成情况是否达标，若存在不符合项，反馈给AI进行修改完善。

4. 当项目整体完成后，可借助其他AI工具再次校验，确认是否完全符合.md需求文件要求、是否存在可优化空间，让AI对完成度进行打分或预估；若仍有优化空间，可让AI生成后续优化的指令提示词，指导进一步完善。

5. 项目优化完善后，让AI根据.md需求文件及实际完成情况，生成项目README.md文档，便于后续查阅、交接及复用。

注意：项目推进过程中，建议及时备份文件或使用Git进行版本管理，避免文件丢失或误操作导致工作返工。
